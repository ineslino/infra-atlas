# Infra Atlas

A reference for the infrastructure stack — open, cross-referenced, and updated daily.

**Live**: <https://infraatlas.dev> *(coming soon)*

A new periodical of cloud and API-management infrastructure. Each "instrument" is a focused reference: regions × instance types × vendors, filterable, searchable, and kept fresh from public APIs.

## Instruments — the convention

Each instrument is a **self-contained folder** with three files:

| File          | Purpose                                                 |
| ------------- | ------------------------------------------------------- |
| `index.html`  | Self-contained UI; tries `./data.json`, falls back to embedded snapshot |
| `data.json`   | Generated by the refresh script; committed to the repo  |
| `refresh.sh`  | Pulls from a **public source** (no credentials) and emits `data.json` |

**Adding a new instrument** (e.g. `azure-vms/`):

1. `mkdir azure-vms && cd azure-vms`
2. Drop in `index.html`, `refresh.sh` (writing to `./data.json`)
3. Add a job to `.github/workflows/refresh.yml`
4. Link to it from the landing's instruments list in `/index.html`

Landing is just an editorial index — instruments are independent.

## Deploy

### Cloudflare Pages

1. Push this repo to GitHub
2. Cloudflare dashboard → **Pages → Create → Connect to Git** → select the repo
3. Build settings:
   - **Framework preset**: None
   - **Build command**: *(empty)*
   - **Output directory**: `/`
4. **Custom domains**: add `infraatlas.dev` and `www.infraatlas.dev`. For a canonical `www → apex` redirect, add a Cloudflare **Redirect Rule** (Rules → Redirect Rules) — the Workers `_redirects` file only supports relative paths, not cross-domain.
5. Cloudflare provisions TLS automatically.

### GitHub Actions data refresh

`.github/workflows/refresh.yml` runs daily at 06:00 UTC. **No cloud account, no credentials, no OIDC** — the workflow only needs `contents: write` to commit. For each data-driven instrument it:

1. Runs the instrument's `refresh.sh` (pulls a public source — see below)
2. Commits the updated `data.json` if anything changed
3. Cloudflare Pages auto-deploys on push to `main`

Manual trigger: **Actions → Refresh data → Run workflow**. Optional instrument input to refresh a single one.

### Data sources — all credential-free

| Instrument        | Source                                                            |
| ----------------- | ----------------------------------------------------------------- |
| `ec2`             | [ec2instances.info](https://instances.vantage.sh) public dataset — `curl --compressed` (~18 MB), no AWS account |
| `regions`         | Curated in `index.html` (no vendor exposes a clean multi-cloud region atlas) |
| `azure-vm`        | Curated in `index.html` (Azure Retail Prices API exists but degrades series naming) |
| `gcp-compute`     | Curated in `index.html` (GCP billing catalog needs an API key) |
| `oci-compute`     | Curated in `index.html` (OCI products API has no per-region availability) |
| `ovh-instances`   | Curated in `index.html` |
| APIM instruments  | Static editorial content — no refresh |

The curated instruments bootstrap `data.json` from the `FAMILIES`/`REGIONS` consts embedded in their `index.html`. To update them: edit the embedded data, delete `data.json`, re-run `refresh.sh`.

## Local development

The site is plain static HTML — no build step. To preview locally with proper `fetch()` for `data.json`:

```bash
python3 -m http.server 8080
# open http://localhost:8080
```

Opening `file://.../infraatlas/index.html` directly works but `fetch('./data.json')` will be blocked by the browser. The embedded snapshot kicks in as fallback.

To regenerate any instrument's data locally:

```bash
./ec2/refresh.sh          # pulls the public dataset — no AWS account needed
./azure-vm/refresh.sh     # bootstraps from index.html
```

Requires `curl`, `jq`, and `python3` — nothing else.
